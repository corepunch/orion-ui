# Предварительный просмотр выписки «Клиент банка»

Это локальный инструмент только для чтения. Он убирает ручной перенос строк
в таблицу для проверки, но не создаёт документы, не меняет остатки Ledger, не
связывает оплату с выставленным счётом и не подключает банк или оператора ЭДО.

## Как воспользоваться

1. В интернет-банке выгрузите выписку в формате «1С:Предприятие — Клиент банка»
   (текстовый файл, не PDF). Выберите один свой рублёвый расчётный счёт и
   запишите его 20-значный номер. Файл может содержать несколько счетов.
2. В корне Orion UI выполните (требуется Lua 5.3 или 5.4), указав свой файл,
   свой счёт и новый путь вывода:

   ```sh
   lua apps/ledger/tools/preview_bank_statement.lua statement.txt 40702810000000000001 > statement-preview.html
   ```

3. Откройте HTML в браузере. Сверьте даты, обороты и остатки с исходной
   выпиской; строки с предупреждениями не используйте без ручной проверки.
   HTML не подключает внешние ресурсы. Не публикуйте и не коммитьте выписку
   или отчёт: оба могут содержать банковские реквизиты и персональные данные.

Для автоматической локальной проверки добавьте `--json` в конец команды:
формат `1c-client-bank-preview-v1`, суммы представлены целыми копейками;
отсутствующий остаток не подменяется нулём.

## Границы проверки

- Поддерживаются версии 1.02 и 1.03, Windows (CP1251), DOS (CP866) и
  экспорт в UTF-8. Свёрка только по выбранному рублёвому счёту; максимум 8 МиБ.
- Направление определяется по полному номеру счёта плательщика или
  получателя. В оборот попадают даты, когда банк списал или зачислил средства,
  а не дата составления документа. Дата и сумма проверяются; помечаются
  неразобранные, дублированные, конфликтующие и не попавшие в период строки.
- Дубли ищутся только внутри текущего файла. При конфликте одного ключа
  видна первая строка, но весь итог требует проверки. Если выписка задаёт
  итоги для того же счёта и периода, они сопоставляются со строками.
- Ключ и правила полей основаны на [формате 1С](https://v8.1c.ru/tekhnologii/obmen-dannymi-i-integratsiya/standarty-i-formaty/standart-obmena-s-sistemami-klient-banka/)
  и [таблице реквизитов](https://v8.1c.ru/tekhnologii/obmen-dannymi-i-integratsiya/standarty-i-formaty/standart-obmena-s-sistemami-klient-banka/formaty-obmena/).
  Проверка на синтетических примерах; реальную выписку банка не проверяли.

Запрос [пользователя Бухонлайн](https://www.buhonline.ru/forum/index?g=posts&t=872765)
шире: одной системой нужны платежи, исходящие и входящие УПД и бухгалтерский
учёт. Печатный УПД не заменяет подписанный документ ЭДО. Для полной
интеграции ещё нужны неизменяемые идентификаторы поступивших документов,
проверка статусов и подписей у конкретного оператора, предложение сопоставлений с
причинами и ручное подтверждение перед созданием черновиков. Текущая
индикация оплаты в карточке Ledger — оценка FIFO по движениям контрагента,
не подтверждение, что конкретный банковский платёж погашает этот документ.
