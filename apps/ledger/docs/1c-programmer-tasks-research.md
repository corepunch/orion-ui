# Работа программистов 1С и возможности ассистента

Дата исследования: 27 октября 2026 года. Для команды Ledger в Orion UI.

50 отдельных публичных обсуждений показывают работу вокруг данных и учётных процессов: программисты сопоставляют объекты при загрузке, строят отчёты, меняют печатные формы, связывают сервисы, настраивают формы и разбирают ошибки исполнения. Во многих случаях бизнес-задача небольшая, но требует знания структуры конкретной конфигурации.

В нашей классификации **39 из 50 кейсов** подходят для подготовки решения ассистентом: 14 — кандидаты на исполнение заранее проверенного сценария, 25 — на генерацию решения с проверкой. Ещё 11 требуют прежде всего диагностики окружения, нагрузки или конфликтов данных. **Это оценка пригодности выбранных кейсов, не доказательство автоматизации 78% рабочего времени.** Чтобы проверить цель «заменить большинство задач», нужен пилот на реальном потоке обращений с учётом времени проверки и исправлений.

## Источники и границы выводов

Выборка: **18 вопросов Stack Overflow на русском и 32 темы Mista**, одна тема — один кейс. Поиск выполнен по задачам Excel/XML, JSON/HTTP/OData, печати, СКД, регламентным заданиям, дублям и производительности. Примеры запросов: `site:ru.stackoverflow.com/questions/ "1с" "СКД"`, `site:forum.mista.ru/topic/ "HTTPСоединение" "JSON"`, `site:forum.mista.ru/topic/ "дубли" "контрагентов"`.

Это целевая качественная подборка, а не случайная выборка профессии: поиск переоценивает вопросы начинающих, ошибки и хорошо индексируемые темы. Авторы включают разработчиков, учащихся и пользователей, которым требуется помощь программиста; их профессиональный статус не проверялся. Вопрос без кода тоже полезен как пример входящего запроса, но не считается опубликованным скриптом. Закрытый вопрос №49 оставлен как пример неуточнённого задания.

Прочитаны доступные фрагменты самих страниц; для №7 и №16 доступны содержательные тексты поискового индекса, а прямое открытие не удалось. Они помечены в карточках. Полнота всех ответов, вложений и изображений не гарантируется. Старые темы отражают задачи своего времени: их код и адреса API нельзя считать актуальными инструкциями без проверки версий.

В каждой карточке «Задача и свидетельство» пересказывает источник. «Что поручить ассистенту», «Проверка» и класс A/B/C — наша оценка, а не утверждение автора темы и не результат испытания модели. Форумные ответы могут быть ошибочными; ссылки подтверждают существование задачи, не сертифицируют решение. Код здесь не запускался в 1С.

## Что строить в Ledger

Есть два разных продукта, которые стоит оценивать отдельно:

1. **Помощник внутри существующей 1С:** читает метаданные конкретной конфигурации, объясняет ошибки, генерирует BSL/запросы/расширения, проверяет их поддерживаемыми средствами 1С. Нужен отдельный адаптер и тестовая база.
2. **Ledger как среда выполнения бизнес-задач:** пользователь просит импорт, отчёт или форму; ассистент выбирает проверенный Lua-сценарий либо готовит дополнение для Ledger. Переносится смысл задачи, а не произвольный BSL.

Начать стоит со второго направления и узких сценариев первого. Общий цикл: запрос пользователя → уточнение периода, объектов и ключей → чтение схемы → план → проверка на копии/предпросмотр → подтверждение изменений → исполнение через API → сверка результата. Исправления справочников, документов и учётных движений должны проходить через соответствующие правила жизненного цикла.

Каталог автоматизаций, доверенные hooks и sandbox дополнений — разные контексты. Наличие Lua не означает безопасный запуск недоверенного кода: локальный runner использует стандартные библиотеки Lua, а read-only ограничивает API изменений Ledger, не файловую систему. В документации также указаны единственный writer XML-базы и отсутствие долговечного журнала планов. Архитектурный аудит отдельно требует исправить атомарность проведения и обработку ошибок перед расширением автоматизации учёта.

### Импорт и обмен данными

#### 07 Импорт вариантов товара из Excel

Источник: [Загрузка товаров с характеристиками из Excel](https://forum.mista.ru/topic/903265) · Класс **B**.

**Задача и свидетельство.** В индексированном обсуждении одна номенклатура с цветом и размером загружается без характеристик; автор показывает структуру исходных строк.

**Что поручить ассистенту.** Разделить сущность товара и варианты; составить сопоставление колонок, ключи и предварительный список создаваемых записей.

**Проверка.** Повторная загрузка не создаёт дублей; все размеры и цвета связаны с правильным товаром. Доступен поисковый текст, открытие страницы не удалось.

#### 39 XML со ссылками между разными конфигурациями

Источник: [Обмен через XML](https://forum.mista.ru/topic/353722) · Класс **B**.

**Что поручить ассистенту.** Создать явное сопоставление типов и идентификаторов, отделить внешнюю ссылку от локального объекта.

**Проверка.** Ссылки разрешаются в нужной базе, новые и повторные объекты обрабатываются одинаково; совпадение полей не означает совместимость типов.

**Что поручить ассистенту.** Определить формат исходных правил и версии инструментов; подготовить карту преобразований и оценку переноса.

**Проверка.** Проверить на реальных форматах правил и целевых релизах; не обещать автоматическую конверсию разных моделей обмена.

## Как проверить замену большинства задач

Предлагаемый пилот: взять **100 последовательных реальных обращений** одной команды или компании, не выбирая только удобные для ассистента. Для каждого сохранить исходное требование, затраченное время специалиста и классификацию; отдельно учитывать новые типы задач, отсутствующие в этой подборке. Работать на обезличенных данных и копии базы с зафиксированными версиями.

Сначала проверить ручной эталон и результат ассистента на одинаковых входных данных. Затем выполнить задачи ассистентом с учётом полного человеческого времени: постановка, уточнения, review, запуск, сверка, исправления и восстановление после ошибок.

| Метрика | Как считать |
|---|---|
| Покрытие | Доля всех поступивших обращений, для которых есть поддерживаемый сценарий |
| Решение без ручного программирования | Доля всех обращений, принятых пользователем, где специалист не писал и не исправлял код; проверку учитывать отдельно |
| Качество первой попытки | Доля результатов, прошедших критерии приёмки без исправления |
| Экономия человеческого времени | 1 − сумма времени людей с ассистентом / сумма времени людей в сопоставимом ручном эталоне |
| Стоимость результата | Время людей + модель + стенд + сопровождение, включая неудачные попытки |
| Целостность | Пропуски/дубли, расхождения сумм, потерянные изменения и успешность отката по каждому запуску |

Цель «большинство задач» считать достигнутой, если **более 50% всех обращений** приняты без ручного программирования при согласованных критериях качества. Цель «большинство работы» требует отдельно **более 50% экономии человеческого времени**. Эти показатели могут сильно различаться: множество коротких настроек не компенсирует одну долгую доработку проведения.

Для каждого сценария нужна карточка исполнения: поддерживаемые конфигурации и версии, входная схема, необходимые права, план изменений, ожидаемый результат, проверки, возможность отмены и журнал. До такого пилота обоснован вывод о перспективных направлениях автоматизации; подтверждённой доли замены программистов эта подборка не даёт.
